### Where the speedup is in the code

Still **no edits inside `f3ast`**. All four replacements are in `nanoscale3d/branch_connections.py` and are turned on together by `install_fast_branch_connections()` (lines 390–406).

| Step | Function | Lines |
| --- | --- | --- |
| Cut the shape into layers | `get_intersection_lines` — test only planes inside each triangle’s Z-range | 277–358 |
| Split each layer into branches | `split_intersection` — node ids from `np.unique` on trimesh `hashable_rows`, instead of `group_rows` plus a Python loop over every endpoint | 29–55 (the new node-id lines are 46–52) |
| Decide which branches touch the layer below | `get_branch_connections` — grid-cell Chebyshev search in `_branch_min_chebyshev` | 175–208, helper 58–127 |
| Place the beam points | `split_eqd` — one equidistant pass per layer, instead of a Numba launch per branch | 211–267 |

Original split, for comparison, is still `f3ast/branches.py` `split_intersection` (lines 9–42). The speedup keeps the same connected-component graph. The node-id lines are:

```python
# nanoscale3d/branch_connections.py, lines 46–52
points = intersection.reshape(-1, 2)
# Same quantization/grouping keys as trimesh.group_rows (tol.merge).
keys = hashable_rows(points)
_unique_keys, node_ids = np.unique(keys, return_inverse=True)
edges = node_ids.reshape(-1, 2)
node_count = int(node_ids.max()) + 1
conn_labels = connected_component_labels(edges, node_count=node_count)
```

Both split paths are Θ(n log n + b n) per layer (n = cut segments, b = branches). The original also pays a Python walk over every endpoint and a second sort. On this mesh that walk is most of the 65.7 s → 24.6 s drop. Branch contact is still the slow step on the fast path (111 s of 170 s).

## 2. LOC vs current repo license

Compared the new LOC (`LOC_SSEC_nanoscale3D-11-6-26`) with the earlier VISS EOI and with this repo’s `LICENSE`.

| Source | License stance |
| --- | --- |
| EOI | Preferred **MIT**; treated F3ast’s **GPLv3** as a constraint if we port/patch F3ast |
| LOC §6.1 | Deliverables are expected to be **derivative of F3ast**, so they **must be GPLv3** |
| `nanoscale3d` today | **BSD-3-Clause** (SSEC base-template default) |

Our current speedups live in `nanoscale3d` and replace F3ast internals (same call sites / stream identity). That is F3ast-derived work under the LOC’s framing. **BSD on this repo does not match LOC §6.1.**

### Proposed fix

- Relicense `nanoscale3d` from **BSD-3-Clause → GPLv3** (same family as upstream F3ast).
- Update `LICENSE`, `pyproject.toml`, and README to state GPLv3 and that this code is a companion to / derivative path for F3ast.
- This does **not** relicense F3ast itself; only SSEC-owned code in this repo.

**SSEC consistency:** Yes for *this* project. The base template’s BSD default is separate; the LOC already chose GPLv3 for F3ast-derived deliverables. Confirm with Engineering Director before merging the license change if that is required process.
